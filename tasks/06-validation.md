# 06. Реализовать правила уведомления

Статус: к выполнению.
Зависимости: 01, 02.
Основание: [план первой версии](README.md), [спецификация](../docs/spec.md), [правила разработки](../AGENTS.md).

## Цель

Определить доменную валидацию без зависимости от HTTP.

## Объём работ

- Определить DTO создания и предметные ошибки валидации.
- recipient_id/type — непустые строки, не только пробелы; сохранять исходное значение и регистр.
- payload — объект JSON; отсутствие превращается в {}, явный null и другие типы запрещены.
- Принимать произвольный непустой type; не проверять существование получателя и поездки во внешних сервисах.
- Статус назначает сервис: created. Сохранять точность чисел payload; согласовать правила с JSONB и ограничениями схемы.

## Проверки

- [ ] Табличные unit-тесты строк, пробельных значений, отсутствующего/пустого/вложенного payload.
- [ ] Проверить отклонение null, массива и скаляров; проверить произвольный type и строковый recipient_id.
- [ ] Проверить точное сохранение JSON-чисел без промежуточной потери точности float64.

## Критерий готовности

Правила проверяются независимо от HTTP; ошибки можно классифицировать через errors.Is/As.

В результате выполнения задачи указать изменённые файлы, выполненные проверки и обнаруженные ограничения.
