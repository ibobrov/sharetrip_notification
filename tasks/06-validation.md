# 06. Доменная валидация уведомления — отменена

Статус: отменено 16 октября 2026 года; актуальный подход к API-валидации определён задачей 09.5.
Зависимости: нет.
Основание: решение придерживаться KISS и проверять входной HTTP-контракт на границе API.

## Решение

Отдельные доменные DTO, валидаторы и предметные ошибки валидации не нужны для первой версии.

- HTTP-слой разбирает запрос через Fiber BodyParser и валидирует DTO через govalidator.
- Отсутствующий `payload` HTTP-слой заменяет на `{}`; отдельной ручной проверки структуры payload нет.
- Сервис получает уже разобранные данные, генерирует UUID, назначает `created` и управляет транзакцией.
- Репозиторий передаёт JSON в PostgreSQL без собственного парсера JSONB и возвращает ошибки с сохранением причины.
- Ограничения хранения проверяет PostgreSQL. API не воспроизводит внутренние правила парсера JSONB.

## Проверки

Отдельных тестов для этой задачи нет. Минимальные проверки входных данных проверялись HTTP-тестом задачи 09.5, удалённым после приёмки.

## Критерий готовности

Задача 06 не создаёт код. Правила HTTP-входа описаны в задаче 09.5.
