# 08. Реализовать создание, получение и транзакции

Статус: к выполнению.
Зависимости: 06, 07.
Основание: [план первой версии](README.md), [спецификация](../docs/spec.md), [правила разработки](../AGENTS.md).

## Цель

Вернуть результат создания только после успешной фиксации.

## Объём работ

- Создать NotificationService и общий helper begin → операция → commit с отложенным rollback.
- Провалидировать данные, сгенерировать UUID v4, назначить created и передать одну транзакцию репозиторию.
- Вернуть полный объект уведомления после успешного commit создания.
- При ошибке не возвращать успешный результат. Для rollback использовать отдельный ограниченный контекст; pgx.ErrTxClosed после commit считать ожидаемым.
- Не вводить автоматические повторы и дедупликацию: одинаковые POST создают независимые записи.

- Реализовать GetNotification по UUID в короткой транзакции без блокировки; pgx.ErrNoRows переводить в предметную ошибку отсутствия. Возвращать полный объект, не изменяя данные.

## Проверки

- [ ] На реальной БД проверить успешный commit и rollback после INSERT при принудительной ошибке callback.
- [ ] Проверить ошибки Begin/Commit и отсутствие результата успеха; управляемую подмену использовать только для трудно воспроизводимых сбоев, не вместо проверки SQL.
- [ ] Проверить отмену контекста и сохранение исходной ошибки.
- [ ] Проверить два создания с одинаковыми данными: разные UUID и две записи.

- [ ] Проверить получение существующего UUID, предметную ошибку для отсутствующего UUID, ошибку БД и неизменность записи.

## Критерий готовности

Успех означает успешный commit; неудача до commit не оставляет запись. Неопределённый исход commit не трактуется как гарантированный rollback.

В результате выполнения задачи указать изменённые файлы, выполненные проверки и обнаруженные ограничения.
