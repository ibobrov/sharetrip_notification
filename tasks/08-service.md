# 08. Реализовать создание, получение и транзакции

Статус: готово к приёмке; интеграционный тест сохранён для просмотра пользователя.
Зависимости: 07.
Основание: [план первой версии](README.md), [спецификация](../docs/spec.md), [правила разработки](../AGENTS.md).

## Цель

Вернуть результат создания только после успешной фиксации.

## Объём работ

- Создать NotificationService и общий helper begin → операция → commit с отложенным rollback.
- Получить уже проверенные API данные, сгенерировать UUID v4, назначить created и передать одну транзакцию репозиторию.
- Не добавлять доменную валидацию: проверка формы входного запроса принадлежит API-задаче 09.
- Вернуть полный объект уведомления после успешного commit создания.
- При ошибке не возвращать успешный результат. Для rollback использовать отдельный ограниченный контекст; pgx.ErrTxClosed после commit считать ожидаемым.
- Не вводить автоматические повторы и дедупликацию: одинаковые POST создают независимые записи.

- Реализовать GetNotification по UUID в короткой транзакции без блокировки; pgx.ErrNoRows переводить в предметную ошибку отсутствия. Возвращать полный объект, не изменяя данные.

## Проверки

- [x] На реальной БД проверить успешный commit и rollback после INSERT при принудительной ошибке callback.
- [x] Проверить ошибки Begin/Commit и отсутствие результата успеха; управляемую подмену использовать только для трудно воспроизводимых сбоев, не вместо проверки SQL.
- [x] Проверить отмену контекста и сохранение исходной ошибки.
- [x] Проверить два создания с одинаковыми данными: разные UUID и две записи.

- [x] Проверить получение существующего UUID, предметную ошибку для отсутствующего UUID, ошибку БД и неизменность записи.

## Критерий готовности

Успех означает успешный commit; неудача до commit не оставляет запись. Неопределённый исход commit не трактуется как гарантированный rollback.

## Результат

Добавлены `internal/service/notification.go` и `transaction.go`. `NotificationService` создаёт UUID v4 и статус `created`, передаёт одну транзакцию репозиторию и возвращает объект только после успешного commit. `GetNotification` выполняет чтение в короткой транзакции и переводит `pgx.ErrNoRows` в `ErrNotificationNotFound`. Валидации входа в сервисе нет.

Один интеграционный тест `internal/service/notification_test.go` использует одноразовую PostgreSQL 16.6 и рабочую Goose-миграцию. Он проверяет успешные commit, два независимых создания, чтение без мутации, rollback после поздней ошибки, ошибки Begin и Commit, отменённый контекст, предметное отсутствие и сохранение исходных ошибок. Тест остаётся в репозитории до подтверждения приёмки.
