# 07. Реализовать пул, сохранение и чтение уведомления

Статус: принято 16 октября 2026 года; интеграционный тест удалён после подтверждения пользователя.
Зависимости: 03, 05.
Основание: [план первой версии](README.md), [спецификация](../docs/spec.md), [правила разработки](../AGENTS.md).

## Цель

Сохранять и читать уведомление по id параметризованным SQL в переданной транзакции.

## Объём работ

- Создать pgxpool с ограничениями и проверкой подключения; закрывать пул при ошибке и завершении.
- Описать entity уведомления и метод INSERT RETURNING с явным списком столбцов.
- Принимать context.Context и pgx.Tx; не выполнять commit/rollback в репозитории.
- Использовать время БД; возвращать сохранённые значения. Сохранять причину ошибки через %w.
- Добавить чтение по UUID с явным списком столбцов без FOR UPDATE; сохранять pgx.ErrNoRows в цепочке ошибки. HTTP-маршрут реализуется в задаче 09.

## Проверки

Helper internal/testdb из задачи 05 удалён пользователем. Перед интеграционными проверками организовать минимальную одноразовую PostgreSQL с миграциями; не считать тестовую инфраструктуру уже готовой и не восстанавливать прежний набор тестов автоматически.

- [x] Интеграционные тесты вставки: UUID, строки, created, UTC-время и payload.
- [x] Проверить вложенный JSON, точные числа и строки со специальными символами.
- [x] Проверить ошибки ограничений и отменённый контекст; после rollback запись отсутствует.

- [x] Проверить чтение сохранённой записи, отсутствие UUID, отмену контекста и отсутствие изменений после чтения.

## Критерий готовности

Репозиторий сохраняет и читает данные без искажений и не управляет прикладной транзакцией.

В результате выполнения задачи указать изменённые файлы, выполненные проверки и обнаруженные ограничения.

## Результат

Добавлены `internal/repository/db.go`, `notification.go` и `entity/notification.go`. `NewPool` создаёт ограниченный `pgxpool`, задаёт таймаут подключения и проверяет соединение через Ping. Репозиторий принимает `context.Context` и `pgx.Tx`, выполняет параметризованные `INSERT RETURNING` и `SELECT` с явным списком столбцов и не управляет транзакцией.

До приёмки один интеграционный тест `internal/repository/notification_test.go` запускал PostgreSQL 16.6 на случайном порту и применял рабочую Goose-миграцию. Были подтверждены UUID, исходные строки, статус, время БД в UTC, вложенный JSON и точное число, чтение без изменения таблицы, rollback, конфликт первичного ключа, `pgx.ErrNoRows` и отмена контекста. После приёмки тест удалён; это исторический результат, а не текущее покрытие.

До удаления теста прошли `make fmt`, `make lint` (0 замечаний), `make build`, `make test` и `git diff --check`. Для Testcontainers `make test` запускался с доступом к Docker; локальная прикладная БД и её данные не использовались.
