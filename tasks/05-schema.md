# 05. Создать схему и тестовую PostgreSQL

Статус: к выполнению.
Зависимости: 03, 04.
Основание: [план первой версии](README.md), [спецификация](../docs/spec.md), [правила разработки](../AGENTS.md).

## Цель

Зафиксировать схему notifications и проверять её на реальном PostgreSQL.

## Объём работ

- Добавить Goose-миграцию <timestamp>_create_notifications.sql с Up/Down.
- Поля: id UUID PRIMARY KEY; recipient_id/type/status TEXT NOT NULL; payload JSONB NOT NULL DEFAULT '{}'; created_at TIMESTAMPTZ NOT NULL DEFAULT now().
- Добавить CHECK для status=created, объектного payload и непустых непробельных recipient_id/type. Явно согласовать определение пробельных символов с доменной валидацией.
- Оставить только индекс первичного ключа; не добавлять history/outbox и межсервисные FK.
- Создать инфраструктуру Testcontainers PostgreSQL 16: запуск, применение тех же миграций, закрытие ресурсов.

## Проверки

- [ ] На одноразовой БД выполнить Up → Down → Up.
- [ ] Прямыми SQL-вставками проверить PK, NOT NULL, CHECK и значения по умолчанию.
- [ ] Проверить автоматическую очистку контейнера и независимость от локальной прикладной БД.

## Критерий готовности

Схема воспроизводима, ограничения подтверждены тестами. Down проверен только на одноразовой БД.

В результате выполнения задачи указать изменённые файлы, выполненные проверки и обнаруженные ограничения.
