# 01. Согласовать контракт первой версии

Статус: к выполнению.
Зависимости: Нет.
Основание: [план первой версии](README.md), [спецификация](../docs/spec.md), [правила разработки](../AGENTS.md).

## Цель

Синхронизировать docs/spec.md с первой версией: создание уведомления через POST и получение через GET.

## Объём работ

- Сохранить в первой версии POST /notifications и GET /notifications/{id}.
- Успех POST: HTTP 201; GET: HTTP 200. В обоих случаях data содержит id, recipient_id, type, status, payload и created_at, errors=[]. Идентификатор в API и БД называется id.
- Сохранить ошибочную оболочку data=null, errors — массив строк; статусы 400, 404, 413, 415, 500.
- Сохранить Location: /notifications/{id} в ответе POST. Обновить примеры, сценарии приёмки и описание локальной проверки.
- Сохранить правила payload, лимит тела 64 KiB и семантику повторного POST из спецификации.

## Проверки

- [ ] Проверить все примеры ответов и упоминания id: публичное поле и поле хранения — id; POST и GET возвращают одинаковый объект.
- [ ] Проверить, что GET входит в критерии готовности: успешное чтение, 400/404/500, неизменность данных и чтение после перезапуска.

## Критерий готовности

Спецификация описывает единственный согласованный контракт без противоречий между примерами и критериями.

В результате выполнения задачи указать изменённые файлы, выполненные проверки и обнаруженные ограничения.
